# Feature Specification: 飞书机器人消息桥

**Feature Branch**: `feat/017-lark-bot-bridge`

**Created**: 2026-11-18

**Status**: Draft

**Input**: 用户描述：基于 DSH 插件模板构造 `dsh-plugin-lark-bridge`。插件只通过 lark-cli 的 bot 身份接收用户消息，以 system-reminder 形式注入会话（没有会话时新建），并提供通知用户的工具。鉴权必须完整，不假设用户已登录 lark-cli。

**变更类别**: 模板转化

**后续变更**: 专用档案、应用凭据与 open_id 手填已被 [022-default-bot-identity](../022-default-bot-identity/spec.md) 取代。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 启动鉴权与弹窗引导 (Priority: P1)

用户安装插件或打开 DSH 时，插件检查 lark-cli、应用凭据、bot 身份与用户授权。鉴权未通过时，Web GUI 出现弹窗说明缺哪一步，并指向插件配置页。

**Why this priority**: 鉴权是所有消息收发的前置条件。没有它，插件无法安全地使用 bot 身份。

**Independent Test**: 在未配置 lark-cli 应用的机器上安装插件并打开 GUI，确认弹窗出现；完成配置页鉴权后，弹窗消失且状态变为就绪。

**Acceptance Scenarios**:

1. **Given** lark-cli 未安装，**When** 插件加载，**Then** 状态为“缺少 lark-cli”，弹窗显示安装入口与配置页入口。
2. **Given** lark-cli 已安装但插件专用配置没有应用凭据，**When** 插件加载，**Then** 状态为“缺少应用凭据”，弹窗提示在配置页填写 App ID 与 App Secret。
3. **Given** 应用凭据有效但尚未完成用户授权，**When** 插件加载，**Then** 状态为“待授权”，配置页提供授权链接与完成按钮。
4. **Given** 鉴权全部通过，**When** 插件加载，**Then** 不出现弹窗，消息监听启动。

---

### User Story 2 - 在配置页完成鉴权 (Priority: P1)

用户在插件配置页填写应用凭据、发起用户授权、查看每一步状态，并可重新检测或重新授权。

**Why this priority**: 鉴权不能依赖终端或假设 lark-cli 已登录。配置页是用户可操作的自助入口。

**Independent Test**: 只使用配置页，从“缺少应用凭据”走到“就绪”，期间完成一次浏览器授权。

**Acceptance Scenarios**:

1. **Given** 用户填入有效 App ID 与 App Secret，**When** 点击绑定应用，**Then** 插件把凭据写入专用 lark-cli 配置并显示 bot 身份检测结果。
2. **Given** 应用已绑定但用户未授权，**When** 点击开始授权，**Then** 配置页显示授权链接，用户可在浏览器完成授权。
3. **Given** 用户在浏览器完成授权，**When** 插件完成设备码轮询，**Then** 状态变为就绪并显示授权用户。
4. **Given** 鉴权失败，**When** 用户点击重新检测，**Then** 配置页显示最新的失败原因与可执行的下一步。

---

### User Story 3 - 飞书消息进入 DSH 会话 (Priority: P1)

用户在与机器人的飞书私聊中发消息。插件以 bot 身份收到事件，把消息内容包成 system-reminder 注入指定工作区的 DSH 会话。会话不存在时创建、修改标题并置顶；存在时复用并记录标识。

**Why this priority**: 这是插件存在的理由：让 AI 借助 bot 与用户双向交互。

**Independent Test**: 配置一个工作区，向机器人发一条私聊消息，确认对应 DSH 会话出现一条 system-reminder 并触发回复。

**Acceptance Scenarios**:

1. **Given** 工作区已配置且没有历史会话记录，**When** 收到第一条用户消息，**Then** 插件在该工作区创建会话、设置标题、置顶，并注入 system-reminder。
2. **Given** 会话记录已存在且会话可恢复，**When** 收到新消息，**Then** 插件复用该会话并注入新的 system-reminder。
3. **Given** 会话已被归档或删除，**When** 收到新消息，**Then** 插件创建新会话并更新记录。
4. **Given** 插件自身发出的消息回显，**When** 收到事件，**Then** 插件忽略该事件。
5. **Given** 同一条消息被重复投递，**When** 再次收到相同消息标识，**Then** 插件只注入一次。

---

### User Story 4 - 通知用户 (Priority: P2)

AI 在会话中调用通知工具，插件以 bot 身份向已绑定的用户发送消息。

**Why this priority**: 让 AI 主动把结果送回飞书，完成双向闭环。

**Independent Test**: 在会话中调用通知工具，确认用户收到 bot 私聊消息，其他会话或用户收不到。

**Acceptance Scenarios**:

1. **Given** 鉴权就绪且已确定用户 open_id，**When** AI 调用通知工具，**Then** 用户收到一条 bot 身份的消息。
2. **Given** 工具调用文本超过单条消息上限，**When** 发送，**Then** 消息被拆分为多条且顺序保持。
3. **Given** 鉴权未就绪或用户 open_id 未知，**When** 调用通知工具，**Then** 工具返回可诊断的失败原因，不发送消息。

---

### Edge Cases

- lark-cli 进程在监听过程中退出：插件按退避间隔重启，并在日志记录原因。
- 用户在工作区不存在或路径不可写时发消息：插件不创建会话，返回明确错误并保持监听。
- 事件负载缺少发送者或会话标识：插件丢弃该事件，不注入空消息。
- 消息内容是图片、文件或富文本：使用 lark-cli 事件提供的可读文本；没有可读文本时注入占位说明。
- 设备码授权过期或用户取消：状态回到待授权，允许重新开始。
- 鉴权在插件运行中被撤销：下一次检测失败后停止监听并恢复弹窗。
- 配置页保存非法工作区路径：配置校验拒绝保存并提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 插件 MUST 只以 lark-cli 的 bot 身份接收飞书消息与发送飞书消息。
- **FR-002**: 插件 MUST 把 lark-cli npm 包作为插件依赖加载，并使用插件专用配置档案，不依赖用户已有的 lark-cli 登录。
- **FR-003**: 插件 MUST 在每次安装后加载和每次 DSH 启动时执行鉴权检查。
- **FR-004**: 鉴权检查 MUST 覆盖 lark-cli 可用性、应用凭据、bot 身份可用性与用户授权四项，并给出当前失败的阶段。
- **FR-005**: 鉴权未通过时，Web GUI MUST 显示弹窗；弹窗 MUST 能跳到插件配置页，并 MUST 允许用户关闭本次提示。
- **FR-006**: 配置页 MUST 支持填写 App ID 与 App Secret、绑定应用、发起用户授权、显示授权链接、重新检测与重新授权。
- **FR-007**: 配置页 MUST 不把 App Secret 写入插件配置；App Secret MUST 只进入 lark-cli 的专用配置。
- **FR-008**: 鉴权就绪 MUST 以 bot 身份可用且能确定用户 open_id 为准；用户 open_id 可由用户授权结果或配置显式提供。
- **FR-009**: 插件 MUST 要求用户配置一个工作区路径，并在路径无效时拒绝创建会话。
- **FR-010**: 收到目标用户私聊消息时，插件 MUST 把消息包成 `<system-reminder>` 并注入该工作区对应的 DSH 会话。
- **FR-011**: 注入 MUST 唤醒会话并产生一个用户轮次；消息 MUST 标明来源是飞书及发送时间。
- **FR-012**: 插件 MUST 持久化工作区会话标识；标识存在且会话可用时复用，不可用时新建并覆盖记录。
- **FR-013**: 新建会话 MUST 设置标题并置顶；配置的标题变化时，复用会话 MUST 同步标题。
- **FR-014**: 插件 MUST 只接受已绑定用户的私聊消息，忽略 bot 自身消息、其他发送者与群聊消息。
- **FR-015**: 插件 MUST 按消息标识去重，重复投递只注入一次。
- **FR-016**: 插件 MUST 提供通知工具，参数为文本；工具 MUST 只向已绑定用户发送，不接受任意接收目标。
- **FR-017**: 通知工具 MUST 以 bot 身份发送，并在文本超过单条上限时按顺序拆分。
- **FR-018**: 通知工具在鉴权未就绪或用户未知时 MUST 返回失败原因，不抛未处理异常。
- **FR-019**: 插件 MUST 在监听断开后自动重启，并在卸载时终止子进程。
- **FR-020**: 插件 MUST 提供中英文界面文案，并移除模板示例工具、示例行与示例配置。
- **FR-021**: 插件 MUST 在日志中记录鉴权阶段变化、会话创建或复用、监听重启与发送失败，且不记录 App Secret。

### Key Entities

- **鉴权状态**: 当前阶段、失败原因、bot 身份状态、授权用户、应用标识与最后检测时间。
- **桥接设置**: 工作区路径、会话标题、lark-cli 可执行文件覆盖、专用配置档案名、用户 open_id 覆盖。
- **会话记录**: 工作区路径、DSH 会话标识、标题、最后消息时间。
- **飞书消息**: 消息标识、发送者 open_id、聊天类型、可读文本、发送时间。
- **通知**: 文本、拆分片数、发送结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全新环境安装插件后，用户只通过配置页即可在 3 分钟内从“缺少 lark-cli”走到“就绪”。
- **SC-002**: 鉴权未通过时，每次打开 DSH 的 30 秒内出现一次可关闭的弹窗。
- **SC-003**: 用户发出私聊消息后 5 秒内，对应 DSH 会话出现 system-reminder 并开始一轮回复。
- **SC-004**: 同一条飞书消息重复投递 10 次只产生 1 次注入。
- **SC-005**: 通知工具调用后 10 秒内，已绑定用户在飞书收到 bot 消息。
- **SC-006**: 关闭再打开 DSH 后复用同一桥接会话，不产生重复会话。
- **SC-007**: 用户在其他飞书群或与其他机器人对话时，插件不向桥接会话注入任何内容。

## Assumptions

- 用户拥有一个飞书自建应用，并能在开放平台配置机器人能力、事件订阅与所需权限。
- 用户可以在浏览器完成飞书 OAuth 设备码授权。
- lark-cli 的 bot 身份通过应用凭据获得，不依赖用户身份登录。
- 插件只服务一个已绑定用户和一个工作区；多用户或多工作区不在本期范围。
- 飞书事件通过 lark-cli 的实时事件消费能力接收，不额外部署公网回调服务。
- 用户的工作区已存在且可读写。
