# Feature Specification: 侧栏在场状态按钮

**Feature Branch**: `feat/042-presence-toggle`

**Created**: 2026-11-24

**Status**: Approved

**Input**: User description: "在侧栏页脚红框位置加一个 icon，实时反映我是否在电脑旁，点击可切换。按钮的位置和样式参考 dsh-plugin-practical-tool-bundle。讨论 icon 的图案和交互。"

## Open Decisions

无。

## Clarifications

### Session 2026-11-24

- [D-001] Q: 在场状态的作用范围是什么？ -> A: 全局唯一状态，取代 `SA-调度会话` 按会话推断的状态，决定调度会话的回复渠道。
- [D-005] Q: 两种状态的图案与配色？ -> A: 在电脑旁为绿色显示器，离开为次要文字色手机。见 [icon-preview.png](./icon-preview.png) 方案 A。
- [D-006] Q: 点击的交互方式？ -> A: 单击立即切换，悬停提示显示当前状态与点击效果。
- [D-002] Q: 状态由哪些事件自动更新？ -> A: 「飞书任务与调度会话」行新增两个配置项，分别控制 GUI 文本输入与飞书输入是否改变状态。
- [D-004] Q: 插件或 DSH 重启后状态如何恢复？ -> A: 不保存，每次启动都是在电脑旁。
- [D-007] Q: 按钮何时显示？ -> A: 本功能属于「飞书任务与调度会话」行，该行启用时显示。
- [D-008] Q: 切换后是否立即通知空闲的调度会话？ -> A: 不唤醒。
- [D-009] Q: `SA-工作会话` 是否也受该状态影响？ -> A: 受影响。调度会话与工作会话都按全局状态处理。系统提示词只说明用户在各位置时如何处理，不含「没有提醒时」的默认；当前位置由 `<system-reminder>` 提醒告知。每个会话必有一条在场提醒，状态切换后在 `agent/pre-step` 重新注入。
- [D-003] Q: 手动切换与自动更新冲突时以谁为准？ -> A: 最后发生的事件为准。
- [D-010] Q: 两个自动更新配置项的默认值？ -> A: 均开启。
- [D-011] Q: 哪些会话的 GUI 文本输入计入？ -> A: 任一会话。
- [D-012] Q: 调度会话何时插入在场提醒？ -> A: 每次模型请求前找出会话中最近一条在场提醒，与全局状态不同或不存在时插入。提醒插入时带属性，属性值标明提醒类型与所记状态；识别提醒与比较状态都按属性值判断，不匹配正文。
- [D-013] Q: 提醒是否写明状态变化的来源？ -> A: 不写。正文见 D-017。
- [D-014] Q: `SA-工作会话` 的本机/远程模式是否只由在场提醒决定？ -> A: 是。删除「调度消息切到远程、直接消息切到本机」的规则。
- [D-015] Q: 工作会话本机模式上报首行「用户在电脑前」是否保留？ -> A: 删除；调度提示词中对应的说明一并删除。
- [D-016] Q: 本机模式下工作会话是否仍上报需求变更、完成与放弃？ -> A: 保留；普通对话不上报。
- [D-017] Q: 提醒正文怎么写？ -> A: 两个预设共用一份正文，只陈述用户当前位置；如何处理由各自的系统提示词说明。
- [D-018] Q: 哪些会话注入在场提醒？ -> A: 只有 `SA-调度会话` 与 `SA-工作会话` 的会话。

### 探索发现

- 参考插件把页脚按钮注册到 `sidebar.footer.action` 槽位：
  - 扫帚为 `order: 50`，重启为 `order: 51`。
  - 按钮为 36×36 圆形、透明底，图标 16 至 18 px、描边 1.8、继承 `currentColor`。
  - 悬停时底色为当前色 12% 混合；`title` 与 `aria-label` 同文案。
  - 侧栏折叠时页脚动作改为纵向一列，手机断点把动作排到设置入口之前。
- 本插件前端目前只注册 `shell.overlay` 与 `plugins.row.config`，未使用 `sidebar.footer.action`。
- `SA-调度会话` 已有在场判定 `src/sa-dispatch/presence.ts`：
  - 状态为 `local` 与 `remote`。
  - `source.kind` 为 `user` 判为 `local`，为 `lark-bridge` 判为 `remote`。
  - 状态按会话记录在内存 `WeakMap`，切换时插入 `<system-reminder>`。
  - 没有提醒时调度提示词按远程处理。
- `SA-工作会话` 按有无 `<dispatch_session_message>` 区分调度消息与本机消息，不读取在场状态。
- 「飞书任务与调度会话」即 `lark-super-agent` 行，目前没有配置项。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼看到当前在场状态 (Priority: P1)

用户打开 DSH，在侧栏页脚看到一个图标，图标形态表明插件当前认为用户在电脑旁还是已离开。

**Why this priority**: 用户需要知道调度会话会把回复送到哪里。

**Independent Test**: 分别在两种状态下打开 GUI，确认图标形态与悬停提示和状态一致。

**Acceptance Scenarios**:

1. **Given** 状态为在电脑旁，**When** 用户查看侧栏页脚，**Then** 显示在电脑旁图标，悬停提示写明当前状态。
2. **Given** 状态为离开，**When** 用户查看侧栏页脚，**Then** 显示离开图标，悬停提示写明当前状态。
3. **Given** 状态被自动更新，**When** GUI 处于打开状态，**Then** 图标在 3 秒内同步，无需刷新页面。
4. **Given** DSH 刚启动，**When** 用户查看侧栏页脚，**Then** 显示在电脑旁。

---

### User Story 2 - 点击切换状态 (Priority: P1)

用户离开电脑前点击图标切换为离开，此后调度会话经飞书联系用户；回到电脑后再点一次切回。

**Why this priority**: 自动判定只能在用户发消息后生效，离开前主动切换才能让后续上报及时送到飞书。

**Independent Test**: 点击图标后，调度会话下一次回复走对应渠道。

**Acceptance Scenarios**:

1. **Given** 状态为在电脑旁，**When** 用户点击图标，**Then** 状态变为离开，图标立即更新。
2. **Given** 状态为离开且调度会话收到工作会话上报，**When** 调度会话转达，**Then** 经 `lark_notify` 发送。
3. **Given** 切换请求失败，**When** 宿主返回错误，**Then** 图标恢复原状态并提示失败。

---

### User Story 3 - 按配置自动更新状态 (Priority: P2)

用户在「飞书任务与调度会话」行的配置中选择 GUI 文本输入与飞书输入是否改变状态。

**Why this priority**: 用户用手机浏览器打开 DSH 时，GUI 输入并不代表人在电脑旁；配置项让用户按自己的习惯取舍。

**Independent Test**: 分别开关两个配置项，发送对应来源的消息，确认状态按配置变化或保持。

**Acceptance Scenarios**:

1. **Given** GUI 文本输入配置开启且状态为离开，**When** 用户在 GUI 发送文本消息，**Then** 状态变为在电脑旁。
2. **Given** 飞书输入配置开启且状态为在电脑旁，**When** 桥接会话收到飞书私聊，**Then** 状态变为离开。
3. **Given** 某项配置关闭，**When** 收到对应来源的消息，**Then** 状态保持不变。

---

### User Story 4 - 工作会话跟随在场状态 (Priority: P2)

用户离开电脑后，工作会话经 `send_report` 与用户交流；回到电脑后，工作会话直接在正文对话。

**Why this priority**: 工作会话与调度会话使用同一份状态，用户只需切换一次。

**Independent Test**: 分别在两种状态下唤醒工作会话，确认交流渠道与状态一致。

**Acceptance Scenarios**:

1. **Given** 状态为离开，**When** 工作会话需要向用户提问，**Then** 经 `send_report` 发送。
2. **Given** 状态为在电脑旁，**When** 工作会话需要向用户提问，**Then** 在正文中提问。
3. **Given** 状态为在电脑旁且任务完成，**When** 工作会话结束任务，**Then** 经 `send_report` 上报完成，正文不含「用户在电脑前」首行。

---

### Edge Cases

- 工作会话收到调度消息时状态为在电脑旁，工作会话仍按本机模式在正文与用户交流。
- 其他预设的会话不出现在场提醒；其中的 GUI 输入仍按开关更新全局状态。
- 多个浏览器页面同时打开时，任一页面切换后其他页面同步更新。
- 侧栏折叠时按钮仍可见、可点击。
- 「飞书任务与调度会话」行停用时按钮消失；重新启用后按钮出现。
- 调度会话正在运行时切换，新状态在其下一次模型请求前生效。
- 调度会话空闲时切换，状态只在它下一次被唤醒后生效。
- 空闲期间来回切换后回到原状态，调度会话不会收到新的提醒。
- 会话压缩移除了在场提醒后，下一次模型请求前补回当前状态的提醒。
- 插件重启后，调度会话按会话中已有的提醒判断，状态一致时不重复插入。
- 手动切换为离开后又在 GUI 发送文本，GUI 文本输入开关开启时状态回到在电脑旁。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「飞书任务与调度会话」行启用时，插件 MUST 在侧栏页脚动作区显示在场状态按钮，位置在参考插件的页脚按钮之后；该行停用时 MUST 隐藏。
- **FR-002**: 按钮尺寸、圆角、悬停效果与无障碍属性 MUST 与参考插件的页脚按钮一致。
- **FR-003**: 在电脑旁 MUST 显示绿色显示器图标，离开 MUST 显示次要文字色手机图标。
- **FR-004**: 用户单击按钮 MUST 立即切换状态，无确认步骤；图标立即反映新状态。
- **FR-004a**: 悬停提示 MUST 写明当前状态与点击后的状态，例如「在电脑旁 · 点击切换为离开」。
- **FR-005**: 状态变化 MUST 在 3 秒内同步到所有打开的页面。
- **FR-006**: 在场状态 MUST 全局唯一，所有 `SA-调度会话` 与 `SA-工作会话` 读取同一份状态选择交流渠道。
- **FR-006a**: 全局状态 MUST 取代按消息来源逐会话推断的状态；会话的提醒只跟随全局状态。
- **FR-006d**: 调度会话与工作会话每次模型请求前 MUST 找出会话中最近一条在场提醒；它不存在或所记状态与全局状态不同时，MUST 插入当前状态的提醒。
- **FR-006e**: 在场提醒插入会话时 MUST 带两项属性：提醒类型为在场提醒，所记状态为 `local` 或 `remote`。识别在场提醒与比较状态 MUST 只按这两项属性值判断，不匹配提醒正文。
- **FR-006f**: 两个预设 MUST 共用同一份提醒正文，正文只陈述用户当前位置，不写处理方式与变化来源。
- **FR-006b**: 状态切换 MUST 不唤醒空闲的调度会话或工作会话。
- **FR-006c**: `SA-工作会话` MUST 只按在场提醒决定本机或远程模式，不再按消息来源切换。
- **FR-006h**: 工作会话本机模式下 MUST 继续经 `send_report` 上报需求变更、完成与放弃，上报正文不加「用户在电脑前」首行；普通对话不上报。
- **FR-006i**: 在场提醒 MUST 只注入 `SA-调度会话` 与 `SA-工作会话` 的会话。
- **FR-006g**: 两个预设的系统提示词 MUST 只说明用户在电脑旁与离开时各如何处理，MUST 不含无提醒时的默认状态。
- **FR-007**: 切换失败时按钮 MUST 恢复原状态并告知用户。
- **FR-009**: 状态 MUST 只保存在内存中，每次插件启动的初始值为在电脑旁。
- **FR-010**: 「飞书任务与调度会话」行 MUST 提供两个开关：GUI 文本输入是否改变状态、飞书输入是否改变状态。
- **FR-011**: 开关开启时，任一会话收到的 GUI 文本输入 MUST 把状态设为在电脑旁，飞书输入 MUST 把状态设为离开；开关关闭时对应来源 MUST 不改变状态。
- **FR-012**: 两个开关 MUST 默认开启。
- **FR-013**: 手动切换与自动更新 MUST 以最后发生的事件为准。
- **FR-008**: 按钮文案 MUST 提供中文与英文。

### Key Entities

- **在场状态**：`local` 表示在电脑旁，`remote` 表示离开。进程内全局唯一，来源为手动切换、GUI 文本输入或飞书输入。
- **自动更新配置**：「飞书任务与调度会话」行的两个开关，默认开启。
- **在场提醒**：调度会话或工作会话中的一条 `<system-reminder>` 消息。属性值标明提醒类型与所记状态，正文只供模型阅读。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户无需打开任何面板即可在 1 秒内读出当前状态。
- **SC-002**: 单击后图标在 200 毫秒内变化。
- **SC-003**: 切换为离开后，调度会话的下一次转达 100% 经飞书发送。
- **SC-004**: 会话压缩或插件重启后，调度会话的下一次模型请求前恰好有一条与全局状态一致的最新在场提醒。

## Assumptions

- 页脚按钮的布局与折叠规则沿用参考插件的做法。
- 状态在本机 DSH 进程内全局唯一，不区分浏览器或设备。
