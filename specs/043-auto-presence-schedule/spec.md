## Clarifications

### Session 2026-11-24

- [D-001] Q: 到点切换与手动切换冲突时以谁为准？ -> A: 时间点只在到点执行一次，不做周期纠偏；用户手动切换后状态保持到下一个时间点（沿用 042 的「最后发生的事件为准」）。
- [D-002] Q: 插件启动或重启时是否补执行？ -> A: 启动时按当天最近一个已过且未被跳过的到点补执行一次；当天没有可用到点则保持「在电脑旁」。
- [D-003] Q: 调休上班日算不算周末？ -> A: 按中国法定日历判断，调休上班日算工作日，不按周末跳过；调休放假日期算节假日。
- [D-004] Q: 节假日数据来源、缓存与降级？ -> A: 运行时联网获取，数据源为 `NateScarlet/holiday-cn`（含 `isOffDay` 与调休），主源 jsDelivr、备源 raw.githubusercontent；本地缓存带过期刷新；获取失败用上次缓存，无缓存时只按周末跳过并记日志与在配置页提示。
- [D-005] Q: 时间格式与精度？ -> A: 24 小时制 `HH:mm`，精确到分钟。
- [D-006] Q: 同一时间点同时出现在两个列表时？ -> A: 以「离开」为准。
- [D-007] Q: 闹钟条目各项默认值？ -> A: 新建条目默认启用、跳过周末、跳过中国法定节假日。
- [D-008] Q: 判定时区？ -> A: 宿主本地时间。
- [D-009] Q: 时间选择控件？ -> A: 引入成熟的第三方时间选择器 `react-time-picker`（表盘式，配 `react-clock`），在 DSH `Modal` 内使用；样式按 DSH 设计令牌覆盖。不使用浏览器原生时间输入，不自绘选择控件。
- [D-010] Q: 闹钟条目的数据形态与展示位置？ -> A: 每条闹钟是一条记录，含时间、动作、启用、跳过周末、跳过节假日；配置页按动作分两个分区展示，两个分区都可多条。

### 探索发现

- 「飞书任务与调度会话」即 `lark-super-agent` 行；行配置页由 `src/client/presence-config.tsx` 注册，槽位键 `dsh-plugin-lark-bridge#lark-super-agent`。
- 行配置 schema 在 `src/lark-super-agent/config.ts`，字段以 `.volatile()` 声明，保存后原地生效。
- 配置页基于 `SettingsFormModel`：字段以文本暂存，保存时写入 `{ op: 'set', path: [field], value }`；因此闹钟列表可以整列作为一个字段的 JSON 文本暂存。
- 在场状态在 `src/lark-super-agent/presence.ts`，进程内全局唯一；路由 `/lark-bridge/presence` 提供读取与手动切换。
- DSH 前端组件库 `@deepseek-ai/dsh-client-ui-primitives` 提供 `Button`、`Checkbox`、`IconCloseOutlineRegular`、`Modal`、`Switch`、`Tag`、`Input`、`SettingsForm` 等；没有时间选择控件。
- 仓库没有 shadcn/ui 依赖；shadcn/ui 也不提供时间选择器。
- `react-time-picker` 8.1.0 提供表盘式时间选择，支持 `portalContainer` 指定弹层挂载点，样式文件 `dist/TimePicker.css` 与 `react-clock/dist/Clock.css` 可用类名覆盖。
- 浏览器产物把非平台模块内联进 `dist/client.js`，CSS 由 `tsdown` 收集后注入，新增前端依赖不需要额外构建配置。
- 数据源 `NateScarlet/holiday-cn` 的年度 JSON 含 `days: [{ name, date, isOffDay }]`；`isOffDay: false` 的日期是调休上班日。2026 年数据 39 条。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按闹钟条目自动切换在场状态 (Priority: P1)

用户在「飞书任务与调度会话」行的配置页添加若干闹钟条目。到达某条闹钟的时间点时，插件把全局在场状态切到该条目对应的动作，调度会话与工作会话随后按新状态选择交流渠道。

**Why this priority**: 在场状态决定调度会话与工作会话把内容发到网页还是飞书；按时间自动切换后，用户不必每次手动点击页脚按钮。

**Independent Test**: 添加两条相隔一分钟的闹钟，等待到点，观察侧栏页脚按钮的图标与文案按条目动作变化。

**Acceptance Scenarios**:

1. **Given** 一条「切换为在电脑旁」的闹钟在 `09:00` 且当前状态为离开，**When** 本机时间到 `09:00`，**Then** 状态变为在电脑旁。
2. **Given** 一条「切换为离开」的闹钟在 `18:00` 且当前状态为在电脑旁，**When** 本机时间到 `18:00`，**Then** 状态变为离开。
3. **Given** 某条闹钟已执行过，**When** 同一分钟内再次判定，**Then** 不重复执行。
4. **Given** 到点时状态已是目标状态，**When** 执行该条闹钟，**Then** 状态与更新时间都不变化。
5. **Given** 所有闹钟条目都被删除或停用，**When** 时间流逝，**Then** 状态不因时间变化。

---

### User Story 2 - 添加与编辑闹钟条目 (Priority: P1)

用户点击分区的添加按钮，在弹窗里自选时间、勾选跳过项后确认，条目以 tag 出现在分区内；点击条目上的设置可再次编辑，点击 x 删除。

**Why this priority**: 没有编辑入口就无法配置自动切换。

**Independent Test**: 添加三条闹钟、编辑其中一条的时间与跳过项、删除一条，保存后重新打开配置页核对。

**Acceptance Scenarios**:

1. **Given** 配置页打开，**When** 用户点击「自动切换在电脑旁的时间」的添加按钮，**Then** 出现可自选时间与跳过项的弹窗。
2. **Given** 弹窗内选定时间 `09:00` 并确认，**Then** 该分区立即出现 `09:00` 的 tag。
3. **Given** 分区内已有 tag，**When** 用户点击该 tag 上的设置入口，**Then** 弹窗显示该条目的当前时间与跳过项，确认后条目更新。
4. **Given** 分区内已有 tag，**When** 用户点击 x，**Then** 该条目从分区移除。
5. **Given** 用户改动后未保存，**When** 用户离开配置页，**Then** 改动被丢弃；点击保存后写入插件配置。
6. **Given** 已保存配置，**When** 用户重新打开配置页，**Then** 两个分区按保存内容展示。
7. **Given** 同分区已有 `09:00`，**When** 用户再次添加 `09:00`，**Then** 分区不出现重复条目。

---

### User Story 3 - 每条闹钟单独设置跳过项 (Priority: P2)

用户为每条闹钟单独设置是否跳过周末、是否跳过中国法定节假日；被跳过的日期不执行该条闹钟，其他条目照常执行。

**Why this priority**: 不同时间点的用途不同，跳过条件需要逐条控制。

**Independent Test**: 两条时间点相同或相近的闹钟，一条开启跳过周末、一条关闭，在周末观察哪条执行。

**Acceptance Scenarios**:

1. **Given** 某条闹钟开启「跳过周末」且当天是周末，**When** 到点，**Then** 该条不执行，其他未跳过的条目照常执行。
2. **Given** 某条闹钟开启「跳过中国法定节假日」且当天是法定节假日，**When** 到点，**Then** 该条不执行。
3. **Given** 某条闹钟关闭两个跳过项，**When** 周末或法定节假日到点，**Then** 该条照常执行。
4. **Given** 某条闹钟停用，**When** 到点，**Then** 该条不执行。
5. **Given** 当天被跳过，**When** 用户在当天手动切换状态，**Then** 手动切换照常生效。

---

### User Story 4 - 手动切换不被自动切换覆盖 (Priority: P2)

用户手动点击页脚按钮切换状态后，状态保持到下一个到点，不会在下一分钟内被拉回。

**Why this priority**: 手动切换表达用户当下意图；自动切换若持续纠偏会让按钮失效。

**Independent Test**: 手动切换后持续观察数分钟，确认状态保持到下一个到点。

**Acceptance Scenarios**:

1. **Given** 刚过某到点且已执行，**When** 用户手动切换状态，**Then** 状态保持到下一个到点。
2. **Given** 用户在到点同一分钟内先手动切换，**When** 该到点判定执行，**Then** 手动切换的结果保留。
3. **Given** 用户通过网页输入或飞书输入更新状态，**When** 时间流逝，**Then** 现有两个输入开关的行为不变，自动切换只在到点执行。

---

### User Story 5 - 配置持久化与数据可用性提示 (Priority: P3)

闹钟条目写入插件配置，DSH 或插件重启后保留；节假日数据不可用时配置页给出提示。

**Why this priority**: 每次重启重配不可接受；数据不可用需要用户知情。

**Independent Test**: 保存配置后重启 DSH，确认条目与设置不变；断网启动后查看配置页提示。

**Acceptance Scenarios**:

1. **Given** 配置已保存，**When** 插件重启，**Then** 配置页展示相同的条目与设置。
2. **Given** 配置已保存，**When** 插件重启，**Then** 自动切换按保存的条目继续生效。
3. **Given** 节假日数据获取失败且无缓存，**When** 用户打开配置页，**Then** 页面提示节假日数据不可用、当前只按周末跳过。
4. **Given** 节假日数据获取失败但有缓存，**When** 到点判定，**Then** 使用缓存数据判定并记录日志。

---

### Edge Cases

- 同一分钟内有「切换为在电脑旁」与「切换为离开」两条闹钟：以「离开」为准。
- 同一分钟内有两条同动作闹钟：只执行一次。
- 用户添加条目后不保存：只有保存后的配置影响自动切换。
- 配置中条目缺少字段或时间非法：插件忽略该条目，配置页拒绝保存非法条目。
- 系统时钟回拨或跨零点：每条闹钟在每个日期最多执行一次；跨零点后按新日期重新计数。
- 主机休眠跨过多个到点：唤醒后只补执行当天最近一个已过且未跳过的到点。
- 插件行停用：自动切换不执行；重新启用后按 [D-002] 补执行。
- 节假日数据未覆盖当前年份：只按周末跳过，并记录日志。
- 到点时页面未打开：状态仍在宿主内切换，页面下次轮询时同步。
- 条目数量很多：配置页仍可正常展示与保存。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「飞书任务与调度会话」行的配置页 MUST 提供「自动切换在电脑旁的时间」与「自动切换离开的时间」两个分区，各自可添加多个闹钟条目。
- **FR-002**: 每条闹钟 MUST 单独保存时间、动作、启用、跳过周末与跳过中国法定节假日五项设置。
- **FR-003**: 闹钟条目 MUST 以 tag 形式展示；每个 tag MUST 带可点击的 x 用于删除该条目，并提供进入该条目设置的入口。
- **FR-004**: 添加与编辑条目 MUST 在弹窗内完成；时间 MUST 使用成熟的第三方表盘式时间选择器自选，MUST NOT 使用浏览器原生时间输入，MUST NOT 自绘选择控件。
- **FR-005**: 弹窗与页面其余控件 MUST 优先使用 DSH 现有组件；新增第三方组件的样式 MUST 按 DSH 设计令牌覆盖。
- **FR-006**: 同一分区内 MUST 不出现重复时间；分区内 MUST 按时间先后展示。
- **FR-007**: 配置页的改动 MUST 经保存写入插件配置；保存前 MUST NOT 影响自动切换。
- **FR-008**: 闹钟条目 MUST 持久化到插件配置，插件或 DSH 重启后保留。
- **FR-009**: 到达某条启用的闹钟时间点时，插件 MUST 把全局在场状态切换为该条目的动作，并遵循 [D-001]、[D-002]、[D-006] 的规则。
- **FR-010**: 每条闹钟在每个日期 MUST 最多执行一次。
- **FR-011**: 目标状态与当前状态相同时 MUST NOT 改变状态或更新时间。
- **FR-012**: 条目开启「跳过周末」时，该条 MUST 在周末不执行；调休上班日 MUST 按工作日处理，见 [D-003]。
- **FR-013**: 条目开启「跳过中国法定节假日」时，该条 MUST 在法定节假日与调休放假日期不执行。
- **FR-014**: 被跳过的日期 MUST NOT 影响手动切换与输入触发的状态更新。
- **FR-015**: 自动切换 MUST 只在到点执行，MUST NOT 周期性地把状态纠偏到「当前应有的状态」。
- **FR-016**: 现有两个输入开关（网页输入切到在电脑旁、飞书输入切到离开）的行为 MUST 保持不变。
- **FR-017**: 自动切换 MUST NOT 唤醒空闲的调度会话或工作会话；状态变化在其下一次模型请求前通过在场提醒生效。
- **FR-018**: 配置页与字典文案 MUST 只表达「自动切换在电脑旁的时间」与「自动切换离开的时间」，MUST NOT 出现「上班」「下班」「通勤」等解释性措辞。
- **FR-019**: 全部新增文案 MUST 提供中文与英文。
- **FR-020**: 时间点 MUST 采用 `HH:mm` 24 小时制，按 [D-005] 判定；判定时区 MUST 按 [D-008] 使用宿主本地时间。
- **FR-021**: 节假日数据 MUST 在运行时联网获取，数据源 MUST 同时给出放假日期与调休上班日期；MUST 缓存到本地并在过期后刷新；MUST NOT 在每次到点判定时请求。
- **FR-022**: 节假日数据获取失败时 MUST 使用上次缓存；没有缓存时 MUST 只按周末跳过，记录日志，并在配置页提示。
- **FR-023**: 插件 MUST 在宿主内以自身定时机制判定到点，MUST NOT 依赖浏览器页面处于打开状态。

### Key Entities *(include if feature involves data)*

- **闹钟条目**：`{ id, time, action, enabled, skipWeekends, skipHolidays }`。`time` 为 `HH:mm`，`action` 为在电脑旁或离开。随插件配置持久化，按动作分两个分区展示。
- **在场状态**：`local`（在电脑旁）与 `remote`（离开），进程内全局唯一；来源为手动切换、网页输入、飞书输入与闹钟条目。
- **执行记录**：某条闹钟在某个日期是否已执行，进程内保存，重启后清空。
- **节假日日历**：日期到「放假 / 调休上班」的映射，按年从网络获取并缓存到本地，含更新时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 到点后 60 秒内，宿主内的在场状态已切换到目标状态。
- **SC-002**: 状态切换后 3 秒内，已打开的配置页与页脚按钮显示新状态。
- **SC-003**: 保存配置后重启 DSH，两个分区的条目与设置与重启前一致。
- **SC-004**: 手动切换后，状态保持到下一个到点，期间不出现被拉回的情况。
- **SC-005**: 被跳过的日期执行 0 次对应闹钟；未跳过的条目照常执行。
- **SC-006**: 一天内节假日数据最多联网获取 1 次。

## Assumptions

- 沿用 042 的在场状态模型、在场提醒与页脚按钮；本功能只新增状态来源。
- 自动切换只在宿主进程内运行；DSH 未运行时不会补执行到点。
- 两个分区默认为空，空表示不做自动切换。
- 配置页位于「飞书任务与调度会话」行，与该行现有的两个输入开关同页。
- 网络与 DNS 可用时才能刷新节假日数据；离线期间依赖缓存。
