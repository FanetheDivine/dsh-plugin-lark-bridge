## User Scenarios & Testing *(mandatory)*

### User Story 1 - 阅读调度会话简介与用法 (Priority: P1)

插件用户阅读 `README.md` 的「关于调度会话」一节，快速了解调度会话的作用、默认预设、派发与接管任务方式，以及任务会话模型与预设的配置入口。

**Why this priority**: 调度会话是插件的核心进阶能力，用户需要简明扼要的上手说明。

**Independent Test**: 检查 `README.md` 的「关于调度会话」章节，确认包含预设说明、新建或接管任务会话、配置页设置项三条核心内容，且不含内部工具名、参数值、轮次上报时机与归档细节。

**Acceptance Scenarios**:

1. **Given** 用户打开 `README.md` 阅读「关于调度会话」，**When** 浏览该节内容，**Then** 能看到桥接会话默认使用 `SA-调度会话` 预设、发消息新建任务会话或给出会话 id 接管已有会话，以及在「调度会话」配置页设置普通/复杂任务模型、默认任务类型与任务会话预设。
2. **Given** 用户阅读「关于调度会话」，**When** 检查行文细节，**Then** 不出现 `session_create`、`task_type`（`common`/`complex`）等内部工具标识，也不出现每轮自动上报与任务归档细节。

### User Story 2 - 阅读在场状态与离开时交互说明 (Priority: P1)

插件用户阅读 `README.md` 的「在场状态」一节，快速了解在电脑旁与离开时的交互方式、侧栏切换入口，以及按输入或定时自动切换的配置。

**Why this priority**: 在场状态直接决定消息通知与任务提问渠道，用户需要清楚离开电脑后如何经飞书继续交互，以及如何手动或自动切换状态。

**Independent Test**: 检查 `README.md` 的「在场状态」章节，确认包含不在电脑旁时的飞书交互说明、侧栏底部图标点击切换、网页/飞书消息自动切换开关、定时切换与跳过周末/节假日配置，且不含控件操作细节与缓存降级规则。

**Acceptance Scenarios**:

1. **Given** 用户打开 `README.md` 阅读「在场状态」，**When** 浏览该节内容，**Then** 能了解在电脑旁与离开时的交互区别（离开时调度会话经飞书联系用户，被管理会话的提问与进度经调度会话发到飞书，用户在飞书回复即可继续），以及侧栏图标切换、网页/飞书输入自动切换和定时切换配置。
2. **Given** 用户阅读「在场状态」，**When** 检查行文细节，**Then** 不出现图标颜色/悬停说明、启动初始态、`HH:mm` 选择器操作、单次触发与节假日联网缓存回退细节。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `README.md` 的「关于调度会话」一节 MUST 精简为三项核心说明：
  1. 桥接会话默认使用 `SA-调度会话` 预设（可在「用飞书和DSH对话」配置页查看或更改）。
  2. 向调度会话发消息可在已登记工作区新建任务会话，也可给出会话 id 接管或取消管理已有会话。
  3. 「调度会话」配置页可设置普通任务模型、复杂任务模型、默认任务类型与任务会话预设。
- **FR-002**: `README.md` 的「关于调度会话」一节 MUST 移除 `session_create`、`task_type`（`common`/`complex`）等工具与参数名称，以及每轮自动上报和任务归档确认细节。
- **FR-003**: `README.md` 的「在场状态」一节 MUST 说明不在电脑旁时的交互方式（在电脑旁时直接在网页对话；离开时调度会话经飞书联系你，被管理会话的提问与进度也经调度会话发到飞书，在飞书回复即可继续），并精简为三项切换与配置说明：
  1. 点击侧栏底部图标切换「在电脑旁」与「离开」。
  2. 「调度会话」配置页支持开启「网页输入时切换为在电脑旁」与「收到飞书消息时切换为离开」。
  3. 同一配置页可添加定时切换时间，并单独设置跳过周末或跳过节假日。
- **FR-004**: `README.md` 的「在场状态」一节 MUST 移除图标颜色与悬停提示、每次启动初始状态、时间选择器点选与 `HH:mm` 输入说明、单次触发与手动保持规则、节假日联网缓存回退，以及停用隐藏细节。
- **FR-005**: 文档修改 MUST 遵守宪章原则 III（文档结构与单一归属）及 `AGENTS.md` 写作规范。

### Key Entities
