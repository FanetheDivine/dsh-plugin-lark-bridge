## Open Decisions

探索结论（来自本仓库与 `dsh-plugin-meta-tools` 的代码与 spec）：

- 桥接会话由 `SessionManager.create` 建立，模型目前取宿主 `agentDefaultModel` 的当前选择；会话建立后没有再次配置模型。
- 插件配置只有 `workspaceRoot`；配置页由鉴权面板、工作区行与保存栏组成。
- 参考插件在配置页的「新增会话」区域提供「模型」行与「预设」行；模型行复用官方模型与推理等级选择器，预设行是 select 触发器加宿主 Menu。
- 参考插件的模型在会话创建后经 `agent.model.select` 写入；预设经 `sessionController.create` 的 `agentPreset` 传入。
- 本仓库依赖锁定 `@deepseek-ai/*@0.2.2-rc.3`，已安装宿主为 `0.2.2-rc.5`；参考插件为预设名册把依赖升级到 `0.2.2-rc.5` 并新增 `@deepseek-ai/dsh-agent-preset-registry`。
- 参考插件在保存的预设不可用时按未配置处理，使用宿主默认。

待确认决策：无，全部决策见 `## Clarifications`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建桥接会话使用配置的模型 (Priority: P1)

用户在插件配置页的「模型」行选择 provider、模型与推理等级并保存。下一条需要新建桥接会话的飞书消息到达时，新会话从首轮开始使用该模型。

**Why this priority**: 桥接会话承担飞书侧的全部工作，模型决定能力与成本；这是本次需求的核心能力。

**Independent Test**: 在配置页选择一组模型与推理等级并保存，清空状态文件后发一条飞书消息，检查新会话的模型选择与首轮使用的模型。

**Acceptance Scenarios**:

1. **Given** 配置页打开，**When** 查看「模型」行，**Then** 界面呈现与 DSH 官方一致的模型与推理等级两级菜单。
2. **Given** 用户查看模型触发器、当前值或模型选项，**When** 模型已被选择或列出，**Then** provider 显示在模型名称前。
3. **Given** 所选模型提供推理等级，**When** 用户打开推理等级选择器，**Then** 只显示该模型支持的等级。
4. **Given** 用户选择模型与推理等级，**When** 保存配置，**Then** 下一条新建的桥接会话使用该选择。
5. **Given** 用户未保存模型配置，**When** 新建桥接会话，**Then** 新会话沿用宿主默认模型。
6. **Given** 用户修改模型，**When** 放弃草稿，**Then** 已保存配置保持不变。

---

### User Story 2 - 新建桥接会话使用配置的预设 (Priority: P2)

用户在配置页的「预设」行选择预设并保存。之后新建的桥接会话运行该预设。

**Why this priority**: 预设决定桥接会话可用的工具与提示词；与模型配合决定会话形态。

**Independent Test**: 在配置页选择一个预设并保存，清空状态文件后发一条飞书消息，检查新会话运行的预设。

**Acceptance Scenarios**:

1. **Given** 配置页打开，**When** 查看模型行下方，**Then** 出现「预设」行，含标签、说明与右侧 select 触发器。
2. **Given** 点击预设触发器，**When** 菜单打开，**Then** 浮窗为宿主自带 Menu，首项为「跟随宿主默认」，其后按宿主顺序列出可用预设。
3. **Given** 用户选择一个预设，**When** 保存配置，**Then** 之后新建的桥接会话运行该预设。
4. **Given** 用户选择「跟随宿主默认」，**When** 保存配置，**Then** 新建桥接会话沿用宿主默认预设。
5. **Given** 已保存预设，**When** 用户放弃草稿，**Then** 已保存值保持不变。

---

### User Story 3 - 配置不可用时的降级与状态 (Priority: P3)

已保存的模型或预设从宿主目录中消失，或名册加载失败时，用户能在配置页看到明确状态；新建桥接会话按宿主默认继续工作。

**Why this priority**: 飞书消息随时到达，配置失效不能阻断消息注入。

**Independent Test**: 保存一个预设后使其在宿主中不可用，打开配置页检查标注；再发一条飞书消息，确认消息被注入。

**Acceptance Scenarios**:

1. **Given** 已保存预设从名册消失，**When** 打开配置页，**Then** 触发器显示该预设并标注不可用，其余可用预设仍可选择。
2. **Given** 预设名册加载失败，**When** 打开配置页，**Then** 显示加载失败与重试，已保存值保留。
3. **Given** 宿主不提供预设名册，**When** 打开配置页，**Then** 选择器禁用并说明原因。
4. **Given** 已保存的模型或预设不可用，**When** 收到需要新建会话的飞书消息，**Then** 新会话按宿主默认建立，消息正常注入。
5. **Given** 已存在的桥接会话，**When** 用户保存新的模型或预设配置，**Then** 该会话继续使用原有配置运行。

---

### Edge Cases

- 模型或预设只包含空白字符时，按未配置处理。
- provider 与 model 缺一时，按未配置处理。
- 已保存模型不在模型目录中时，保留配置，选择器显示未选择状态。
- 所选模型没有推理等级元数据时，隐藏推理等级控制。
- 预设名册为空时，菜单只有「跟随宿主默认」。
- 预设名称缺失时，菜单与触发器显示预设标识。
- 预设名称变化、标识不变时，选择保持不变，显示新名称。
- 名册加载失败后恢复时，重试能读到新名册。
- 配置页只读、保存失败与热更新时，模型行与预设行沿用现有配置页行为。
- 桥接会话已归档时，下一条消息建立新会话并应用配置。
- 配置保存后无需重启插件与宿主。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 配置页 MUST 提供「模型」行，使用与 DSH 官方一致的模型与推理等级选择器，并支持目录加载、搜索、键盘操作、错误与空状态。
- **FR-002**: 模型触发器、当前值与模型选项 MUST 把 provider 显示在模型名称前。
- **FR-003**: 推理等级选择器 MUST 只提供所选模型支持的等级；模型没有推理元数据时 MUST 隐藏该控制。
- **FR-004**: 配置页 MUST 在模型行下方提供「预设」行，包含标签「预设」、说明文案与右侧 select 触发器。
- **FR-005**: 预设菜单 MUST 使用宿主自带 Menu，首项为「跟随宿主默认」，其后按宿主顺序列出可用预设。
- **FR-006**: 模型与预设选择 MUST 只修改配置草稿；保存后生效，放弃草稿时恢复已保存值。
- **FR-007**: 新建桥接会话 MUST 使用已保存的模型配置；未保存时 MUST 沿用宿主默认模型。
- **FR-008**: 新建桥接会话 MUST 使用已保存的预设；未保存时 MUST 沿用宿主默认预设。
- **FR-009**: 已存在的桥接会话 MUST 保持其模型与预设，配置变更只作用于之后新建的会话。
- **FR-010**: 已保存的预设不在宿主可用名册中时，系统 MUST 按未配置处理，使用宿主默认预设，并保留配置值。
- **FR-011**: 已保存的模型不可用时，系统 MUST 按未配置处理，使用宿主默认模型，记录日志，并完成会话创建与飞书消息注入。
- **FR-012**: 模型与预设配置 MUST 只影响桥接插件新建的会话，MUST NOT 修改宿主默认。
- **FR-013**: 模型与预设 MUST 相互独立，可分别设置与清空。
- **FR-014**: 配置页 MUST 保留现有鉴权面板、工作区选择与保存栏行为。
- **FR-015**: 预设名册加载失败 MUST 显示失败与重试；宿主不提供名册时 MUST 禁用选择器并说明原因。
- **FR-016**: 已保存的模型离开目录时，配置页 MUST 保留该值并显示未选择状态；已保存的预设不可用时，配置页 MUST 保留该值并标注不可用。

### Key Entities *(include if feature involves data)*

- **模型配置**: 新建桥接会话的 provider、model 与可选推理等级；三者共同决定会话从哪一轮开始使用该路由。
- **预设配置**: 新建桥接会话的预设标识；空值表示跟随宿主默认。
- **桥接会话**: 由状态文件记录的单一会话，含 `sessionId` 与工作区；归档后按需新建。
- **模型目录**: 宿主按 provider 分组的可用模型及各自支持的推理等级。
- **预设名册**: 宿主提供的预设列表，含标识、名称、说明与可用状态。
- **配置草稿**: 配置页中尚未保存的模型与预设选择。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 新建桥接会话（首次创建与归档后重建）使用已保存的模型与预设。
- **SC-002**: 100% 已存在的桥接会话在保存新配置后保持原有模型与预设。
- **SC-003**: 配置页显示「模型」行与「预设」行，文案与位置和参考插件一致。
- **SC-004**: 保存配置后，下一次新建会话即使用新配置，无需重启插件或宿主。
- **SC-005**: 100% 配置不可用的场景下，飞书消息仍被注入，会话按宿主默认创建。
- **SC-006**: `pnpm check` 与 `pnpm build` 通过。

## Assumptions

- 宿主提供会话级模型选择、模型目录、预设名册与自带 Menu。
- 配置值使用宿主标识，模型目录与预设名册以标识区分条目。
- 一个工作区对应一个桥接会话，配置对该会话之后的新建会话生效。
- 配置页继续由插件管理器打开，布局沿用现有行式配置。
- 全部 `@deepseek-ai/*` 依赖升级到 `0.2.2-rc.5`，与已安装宿主一致。
- README 由另一变更维护，本次不改动。
- 本需求只扩展新建桥接会话的能力，不提供修改已有会话模型或预设的操作。
