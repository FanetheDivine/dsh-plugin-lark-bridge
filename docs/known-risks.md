# 已知风险

## 宿主版本

- `@deepseek-ai/dsh-*` 处于 rc 阶段，接口可能在版本间变化。
- 插件依赖的 `dsh-*` 版本应与运行它的 DSH 版本一致；当前锁定 `0.2.2-rc.5`。
- 实机测试按 `@deepseek-ai/dsh-agent` 的版本选择宿主，版本不一致时安装到 `~/.dsh-local/dsh-<版本>`，全局安装保持不变。

## 官方模型选择器与预设名册

配置页的模型行复用官方 `ModelSelect`，预设行读取 `remote.agentPresets`。

- 选择器从 `@deepseek-ai/dsh-client-ui-model-selection/src/` 直接导入源码，宿主升级可能改变文件布局。
- 选择器自带 CSS module，构建时经 `@tsdown/css` 注入 `dist/client.js`；产物不得残留 `dist/client.css`。
- 浏览器产物依赖宿主静态种子模块 `@deepseek-ai/dsh-client-store`。
- 宿主不提供预设名册时，预设选择器禁用，新建会话沿用宿主默认预设。
- 已保存的模型或预设从宿主目录消失时，新建会话回退宿主默认，配置值保留。

## 安装 rc 依赖

pnpm 的 minimum release age 策略会拒绝发布时间过短的包。

- `@deepseek-ai/dsh-*` 依赖未列入 `minimumReleaseAgeExclude` 时，`pnpm install` 失败。
- 列入规则见[宪章](../.specify/memory/constitution.md)原则 I。

## 共享宿主实例

插件运行时使用宿主提供的 cordis、dsh-tools 与 zod。

- 这些包被打进 bundle 时会产生第二份实例，类型判断和服务注入随之失效。
- 保持 external 的规则见 [how-it-works.md](./how-it-works.md#依赖)。

## 本机 lark-cli

插件使用宿主进程环境解析到的本机 `lark-cli`。

- 命令缺失或无法启动时，CLI 显示未连接；在终端执行 `lark-cli --version` 检查安装与命令解析。
- 正在运行的 DSH 可能保留启动时的环境。安装、升级或修改 `PATH` 后重启 DSH，再执行完整检测。
- 完整检测使用 `auth status --verify`，需要网络。界面只显示笼统连接状态，命令详情查看后端日志。
- 插件不检查最低版本；本机命令不支持所用参数时，检测显示未连接，通知工具返回实际命令错误。

## 本机配置与登录

插件使用 lark-cli 当前生效的配置。

- 终端里切换 lark-cli 的生效配置会同时改变插件使用的机器人，下一次检测或重启监听后生效。
- 用户登录只请求 `auth:user.id:read`，新令牌会替换终端里同一配置原有的授权范围，需要时重新授权其他 scope。
- 旧版本创建的专用配置 `dsh-lark-bridge` 保留在 lark-cli 中，插件不会读取或删除它。

## 飞书开放平台

插件无法代替用户配置应用。

- 未订阅 `im.message.receive_v1` 时，`event consume` 可能启动但收不到消息。
- 缺少 `im:message:send_as_bot` 时，通知工具返回权限错误。
- 缺少 `im:message.p2p_msg:readonly` 时，事件订阅校验失败。
- 事件订阅与权限变更需要重新发布应用版本后生效。

## 事件流

`event consume` 依赖本地事件总线守护进程。

- 守护进程异常退出时，子进程关闭，插件按退避重启。
- 飞书按 `15 秒 / 5 分钟 / 1 小时 / 6 小时` 重推未确认事件。插件过滤 `create_time` 早于监听启动时刻的消息，因此配置完成前的消息不会补投。
- 消息到达后逐条立即注入；会话运行中并入当前轮的下一步，空闲时开新轮。连续消息的合并回复由提示词规定，程序不合并。
- 同一应用配置多个消费者时，每个消费者都会收到事件；本插件按消息标识去重，避免同一实例重复注入。
- 多个 DSH 实例加载本插件时，每个实例都会创建自己的桥接会话并各自注入。

## 通知工具可见性

- 可见性依赖宿主 `when` 条件按步求值；宿主改变条件语义时，工具可能在非桥接会话出现或全部不可用。
- 执行体在缺少 agent 时拒绝发送；宿主改变该字段的填充方式会让工具一律返回 `not-bridge-session`。

## 提醒与压缩

- 回复规则写在固定中文提醒里，模型是否遵守需要人工验收；正文最多一句的规则同样依赖模型遵守。
- 压缩由宿主后端执行。插件在 `agent/pre-step` 检查表层并在缺失时补回，补回发生在下一个模型请求之前。
- 旧版本创建的会话不在支持范围；其中的历史消息不是 `<lark-message>` 块。

## 浏览器路由

鉴权界面通过同源 JSON 路由读取状态。

- 路由只在 `ctx.webServer` 存在时注册；宿主未加载 HTTP 服务时，配置页与弹窗保留检测入口和笼统状态。
- 非回环来源与非同源 `Origin` 被拒绝；远程访问模式需要通过宿主自身的认证。
- 状态请求失败时保留上一份状态，界面不显示网络或 CLI 原始错误。

## 配置面板

- 只有标记 `.volatile()` 的字段出现在“插件”面板的配置页。
- 配置被更高层覆盖时，宿主拒绝保存，表单保留草稿并提示未接受。
- 表单命名空间是插件行在 profile 里的 id；`plugins.row.config` 的键是 `<包名>#<行 id>`。
- 配置页依赖 `dsh-client-ui-plugin-manager` 与 `dsh-client-ui-settings`；两个槽位共用 `configForms`。
- 工作区选项通过 `dsh-client-ui-workspace` 提供的 `useWorkspaces` 读取；提供方不可用时选择器没有注册数据。

## 工作区注册与路径

- 删除注册不会删除磁盘目录；插件以注册关系判断有效性，目录仍存在也会停止监听。
- `domain/changed` 是宿主通用存储事件，插件版本需要与宿主版本对齐。
- Linux 风格盘符路径在 Windows Host 边界转换回原生路径；归一化不解析符号链接。
- 异步注册解析使用序号丢弃旧结果，最终注入前再次校验，覆盖删除与消息处理的竞争。

## 严格配置

配置中出现未知键或非法值时，插件加载失败。

- 用户在 `cordis.patch.yml` 写错键名会导致插件停用。旧版本的 `profile`、`ownerOpenId`、`larkCli`、`sessionTitle` 与 `authCheckOnStartup` 例外，加载时被丢弃。
- 用 `dsh --profile <profile> --dump-config` 检查最终配置。

## 国际化

- 宿主在注册时捕获的文案保持注册时的语言；槽位渲染的文案随切换更新。
- 元数据或字典缺当前语言时按回退链取值。
- 规范见 [i18n.md](./i18n.md)。

## lark-super-agent

### 状态文件

- 调度服务读取本插件 `state.json` 的 `sessionId` 与 `workspaceRoot`。
- 修改状态文件的路径或字段时，必须同步调度服务；否则调度会话解析与上报投递失效。

### 全局工具叠加

- 全局行与预设子行的工具叠加，`SA-调度会话` 的实际工具集取决于整个 profile。
- 其他插件可能增加工具或引入同名工具，本行不收窄全局工具。

### 旧版组合包并存

- 仍含该功能的旧版 `dsh-plugin-practical-tool-bundle` 同时启用时，`lark-super-agent` 行、两个预设与调度工具重复注册。
- 插件不检测这种情况，用户应升级或停用组合包中的该功能。

### 独立 meta-tools 重复

- 独立安装的 `dsh-plugin-meta-tools` 与本插件预设子行同时启用时，同名工具会注册两次。
- 用户应停用独立安装的行或预设内的 `meta-tools` 子行。
- 预设内的 `meta-tools` 子行必须保持 `session_create: false`。改为 `true` 时，同一作用域的 `session_create` 注册两次：后注册者失败。`sa-dispatch` 失败时记警告，调度会话使用 meta-tools 的版本，任务会话模型与预设不生效；meta-tools 先失败时，它的 `session_stop` 与 `session_send` 同组未注册。

### 预设默认与改选

- 桥接会话的预设默认为 `SA-调度会话`，新装后无需手动选择。
- 改选其他预设后，桥接会话缺少调度工具与提示词，插件不提示该问题。

### shell 后台任务

- `SA-调度会话` 不含 `tool-jobs`，shell 工具没有 `run_in_background` 参数。
- 命令超时后会被终止，不会转入后台任务。

### 被管理会话与调度消息

- 宿主把被管理会话收到的调度消息折叠显示为「收到执行请求」，界面看不到标记块原文；宿主改变折叠规则后界面可能直接显示标签。
- 剥掉 `session_send` 的 `<system-reminder>` 帧依赖 meta-tools 的帧格式。上游改变格式后剥离不生效，消息显示两层帧，投递不受影响。
- 调度会话把飞书原文的 `<lark-message>`、`<quote>` 块贴进 `session_send` 时，正文里仍有内容级块。
- 其他会话经 meta-tools 发给被管理会话的消息也会被标为调度消息。

### 任务会话模型与预设

- 只有 `SA-调度会话` 的 `session_create` 套用该模型与预设；其他路径新建的会话保持宿主默认。
- 选择只写入新会话本身，不改变宿主默认模型，也不改变「用飞书和DSH对话」配置页的模型。
- 恢复历史会话与 `/clear` 不重新选择模型。
- 覆写的 `session_create` 复制了 meta-tools 0.1.7 的创建流程。升级 meta-tools 后该工具的参数或语义变化不会同步，升级时需对照。
- meta-tools 行配置的默认模型与默认预设对 `session_create` 不再生效；`session_create` 没有 `agent_preset` 参数。
- 依赖宿主 `sessionController` 的 `create`、`rename`、`resolveAgent` 与 `Agent.model.select`、`Agent.steer`。

### 任务归类与结束

- 任务归类、首条要求范围与按 `kind` 更新状态都由 `SA-调度会话` 按提示词执行，程序不校验。
- 判断引用属于哪个任务只靠调度会话的上下文；压缩后丢失通知原文时，可能需要询问用户。
- 任务是否完成由调度会话判断。调度会话判断失误时，任务会提前结束或长期不结束。
- 报告是否充分、是否通知用户、是否请任务会话重发、用户消息是否转发都由调度会话按提示词判断，程序不校验，也不限制重发次数。模型可能漏回消息、重复通知或反复请求重发。
- 重发请求会让任务会话开新一轮；该轮若没有调用 `send_report`，其自动上报同样进入调度会话。
- 结束任务不归档会话，会话列表可能积累已结束任务的会话。

### 任务日志

- 日志只记用户在 GUI 直接发给被管理会话的消息与用户主动停止，调度会话仍看不到任务会话的其他内部活动。
- 用户主动停止与归档引发的取消使用同一取消原因，插件以会话是否已在归档集合内区分；宿主改变归档与停止的先后顺序后，归档可能被记成用户停止。
- 日志归档后只作历史留存，插件与调度会话都不再读取。
- 日志平时不 git 提交，崩溃或手工清理工作区时未归档的日志可能丢失；归档时才随任务提交。
- 日志注入依赖 `Session.eventAt` 与 `session.seq` 遍历完整事件日志，长会话重建缓存时线性扫描；宿主改变这些接口后注入失效，日志文件不受影响。
- 注入消息的条目 `id` 同时写在来源之外的消息正文中，调度会话的会话日志被手工编辑后可能重复注入。

### 被管理会话

- 「被管理」由 `message-task-status.json` 决定。手工修改台账会让管理状态与真实会话不一致。
- 台账格式校验不通过时按空台账处理，下次写入覆盖旧内容。旧内容只保留在 git 历史中。`task_update` 与 `task_end` 遇到这种台账时直接报错。
- 结束正在等待的提问依赖宿主网关的私有成员 `pendingRemoteEvents` 与 `cancelRemoteEvent`。宿主升级后可能失效，失效时提问保持等待并记一条警告。
- 拦截代为上报后结束轮次依赖宿主的 `concludeTurn` 数据通道（`0.2.2-rc.5` 已验证）。通道改名或语义变化时，被拦截的提问仍会上报，但轮次继续到模型自然收尾。
- 同一会话有多条并发提问时，网关只按会话取消，插件无法区分具体一条。
- 自动上报要求会话没有运行中的子代理。子代理归属于其他会话时不影响判断。
- 自动上报取该轮最后一条助手文本；模型把结果分散在多条消息中时只上报最后一条。
- S 是一条临时指令，模型可能继续遵守它；插件只在下一次模型请求前插入，不提供相反的提醒。

### 上报卡片

- 上报卡片依赖宿主 Chat 的 `conversation.chat.node` 槽位、`ChatNodeDataMap` 声明合并与 `uiConversation.events` Definition 注册。宿主改动这些接口后卡片不显示，工具行照常显示。
- 成功上报在过程分组里保留一行宿主默认工具行，卡片在轮次层级另外显示一次。
- 结果对应的 `tool/call` 不在已加载窗口内时，卡片只显示回执，参数字段为空。

### 通知正文卡片

- 通知卡片与上报卡片使用同一套宿主 Chat 接口；接口变化时工具行仍由宿主显示。
- 成功识别依赖 `lark_notify` 的结果 render 文案，新旧文案都识别。文案再次变化时不再产生卡片，发送行为不受影响。
- 结果对应的 `tool/call` 不在已加载窗口内时没有正文来源，因此不产生空卡片。
- 没有 `task_id` 的新通知不显示会话；旧通知没有 `tool/result.meta` 时只显示正文，无法补回来源会话。
- 卡片模式依赖飞书客户端 7.20 及以上的 Card 2.0 与折叠面板；旧客户端只显示标题。拆成多张卡片时，代码块等跨段 Markdown 结构可能被段落边界截断。
- 多段或多张发送中途失败时，已发出的消息不撤回，靠调度会话按错误说明补发剩余部分；`idempotency-key` 每次调用重新生成，整批重试会重复发送。
- 会话链接依赖 `useWorkspaces` 的工作区成员关系与归档状态，以及 `uiWorkspace.openSession`。宿主改变这些接口后入口退化为只读标识或无法跳转。

## Windows 长路径

`node_modules` 嵌套很深，路径可能超过 Windows 的 260 字符上限。

- `git worktree remove` 此时报错 `Filename too long`。
- `finish-worktree.sh` 遇到该错误时用 Node.js `rmSync` 删除目录，再运行 `git worktree prune`。
