# dsh-plugin-lark-bridge

[![npm](https://img.shields.io/npm/v/dsh-plugin-lark-bridge?logo=npm&label=npm)](https://www.npmjs.com/package/dsh-plugin-lark-bridge)

借助 lark-cli，让 DSH 以飞书机器人身份和你私聊对话。

## 使用

1. 安装或升级 lark-cli：

   ```sh
   npm install -g @larksuite/cli@latest
   ```

2. 配置机器人身份：

   ```sh
   lark-cli config init
   ```

3. 登录授权用户：

   ```sh
   lark-cli auth login --scope auth:user.id:read
   ```

4. 在「用飞书和DSH对话」的配置页选择工作区。
5. 在飞书私聊机器人，与 DSH 对话。

## 关于调度会话

本插件提供 `SA-调度会话` 预设，用于派发与统一管理任务会话。

- 桥接会话默认使用 `SA-调度会话` 预设，可在「用飞书和DSH对话」配置页查看或更改。
- 向调度会话发消息会在已登记的工作区新建任务会话；给出已有会话的 id 也可接管它或取消管理。
- 让调度会话列出当前可用的模型时，它会用 `list_models` 查询宿主模型目录，并可用结果指定任务会话的模型。
- 让调度会话切换某个会话（任务会话或它自己）的模型时，它用 `session_model` 指定 provider、model 与 effort，从该会话下一步生效；只改该会话，不改新建会话的默认模型。
- 已归档的会话可用 `session_restore` 恢复：解除归档、恢复因归档结束的任务及其报告，并重新置顶；`pin: false` 可跳过置顶。
- 「调度会话」配置页可设置「普通任务模型」、「复杂任务模型」、默认任务类型与「任务会话预设」；未选择时跟随宿主默认。
- 任务会话成功上报后，对话里出现一张上报卡片，显示类型、任务简介、正文与附件，轮次折叠后仍可见。点击附件在右侧栏打开。
- 调度会话被归档或不存在时，上报仍先存档，再自动新建调度会话并投递；未送达的报告在下次投递或新建会话时补齐，调度会话先读全部未读报告。
- 调度会话收到消息后立即回复，并对每个任务单独通知：下发指令后马上告诉你结果，报告只在有新结果、里程碑、阻塞、失败或提问时才通知。不是给任务会话的话（例如「先别动」）只记录，不转发。
- `lark_notify` 支持卡片模式：一句总结常显，完整 Markdown 默认收起，展开后可读；长报告由调度会话主动使用。带任务 id 时，飞书消息标明任务，对话里的通知卡片显示任务 id 并可跳转到任务会话，已归档会话显示「已归档」标记。上报与通知正文均与对话正文同色。
- 你直接在任务会话里输入的消息或停止的轮次，调度会话下一次运行时会收到，据此更新任务状态，不会再向你重复提问。

## 回复渠道

桥接会话的回复经飞书送达：完整内容在飞书通知里，正文最多一句概述。任务会话需要你决定时，通过调度会话发送提问报告，写清任务目的、当前进展、问题和选项。你可以在飞书回复，不用打开任务会话的提问面板。
